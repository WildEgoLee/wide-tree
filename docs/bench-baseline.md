# v1 微基准

没有改投影。`make bench` 用同一种拆法加密采样，看成本在哪一档越过 1 µs、10 µs、100 µs 和 1 ms。没有第二套基准，也没有为它加测试钩子。

| 形状 | 固定什么 | 变化什么 |
| --- | --- | --- |
| `wide` | K = 1，S = 2 | N，从 1 万到 400 万 |
| `split` | 扇出 10 万，展开的孩子都挂在同一个父节点上 | K 从 11 到 16001，S = 2K |
| `chain` | 每个父节点只有一个展开孩子 | 链长从 250 到 4 万，稀疏索引的 parent 数约等于 N |

K 是 `memory().expandedCount`。这些形状里每个已展开节点都可达。没有 `rowAt()`；行到节点的定位是 `rowRef`。`expand` / `collapse` 不含 `rowRef`。数字是 5 次试验的中位数，GCC 12.2 `-O2`，2026-09-26 在同一台机器上跑的，不是 CI 门槛。单位是微秒。

## 当时不升级段数组

采样把门槛分开了。该换的后来只有索引的分配方式。

- 段数组继续留着。百万叶子、S = 2 时，查询不变，toggle 是 3.7 µs。单父节点下要到大约 1 万段，expand 才过 100 µs；`rowOf` 在 3 万段仍是 17 µs。
- 一个父节点下的长 `vector` 也继续留着。collapse 到 S = 32002 仍是 4.6 µs。
- `rowRef` 和首屏填充在整个采样里都低于 0.4 µs。
- 最先越过 100 µs 和 1 ms 的是「很多 parent 的 `std::map` 整份拷贝」：大约 2 千个 parent 过 100 µs，大约 1 万到 2 万个 parent 过 1 ms。这一档后来换成了共享的打包索引，见下一节。段数组当时没换，现在也还没换。

## 2026-09-30：索引改成共享的两块数组

同一套三种形状，GCC 12.2 `-O2`。投影的可观察行为不变。稀疏索引不再是每个 parent 一个 `std::map` 节点：一段按 parent 排好的 span，一段 ordinal。候选和当前视图共享这份载荷，直到某个 parent 的 span 真的被改。根的展开和折叠不改索引，所以链上的根切换不再整份拷贝。

wide 仍是位图。400 万节点的 expand / collapse 是 13.2 / 13.4 µs，改前是 13.0 / 13.4 µs。读 64 行和 `rowRef` 仍在 0.3 µs 以下。

单父节点的 expand 仍是段重建。S = 32002 这一档是 354 µs，改前 369 µs。collapse 不再复制那条 ordinal 数组，从 4.3 µs 降到 1.3 µs。`rowOf` 的循环没改，但同一档从 17 µs 变成 33 µs；S = 8002 是 8.3 µs，S = 16002 是 16.6 µs。10 µs 的跨越从「16002 到 32002」挪到「8002 到 16002」。3 万段仍没到 100 µs。

链是这次要看的形状。collapse 不再跟着 parent 数走。expand 还要把整条链投成段，所以它还在。

## 2026-09-30：父节点查找改成开放寻址

投影恢复对每个展开节点在 span 表上二分。链上这是 K log K 次比较，和把段写出来叠在一起。索引载荷上加一张 parent → span 的开放寻址表，装载不超过一半，span 表改动时整张重建。根切换仍然共享整份索引，不重建这张表。

wide 不动。400 万节点的 expand / collapse 是 12.9 / 13.0 µs。

单父节点 `rowOf` 回到改索引之前的一档：S = 32002 是 17 µs，S = 16002 是 8.4 µs。10 µs 的跨越回到「16002 到 32002」。expand 仍是段重建，S = 32002 是 360 µs。

链的 collapse 仍在 1 µs 附近（4 万层 1.2 µs）。expand 掉的是那一截二分：

| ---: | ---: | ---: | ---: | ---: |
| 250 | 7.2 | 7.2 | 0.216 | 8 KB |
| 1,000 | 61 | 29 | 0.252 | 32 KB |
| 2,500 | 161 | 81 | 0.286 | 103 KB |
| 5,000 | 341 | 152 | 0.363 | 206 KB |
| 10,000 | 781 | 310 | 0.608 | 412 KB |
| 20,000 | 1,651 | 967 | 0.915 | 824 KB |
| 40,000 | 3,402 | 2,573 | 1.235 | 1.6 MB |

4 万层的 expand 从 3.4 ms 到 2.6 ms。1 ms 的跨越从「1 万到 2 万」挪到「2 万到 4 万」。100 µs 从「1000 到 2500」挪到「2500 到 5000」。剩下的时间是沿着链把每个段写进数组，大约每个段 64 ns。索引从 640 KB 涨到 1.6 MB，因为多了这张表；它跟 span 一起共享，根切换不复制。

段数组还是不换。再往下要降的是「展开时必须物化 S 个段」，不是查找。一个 parent 下的 ordinal 仍是一段连续内存。
